# Qualify Aegis 2.0.0 for echelon-current 1.40.0 (Conditor)

Source: owner request, 2026-11-25: "Move the echelon current" — move
echelon-current to Aegis 2.0.0. The Registry cut is echelon-registry#115
(echelon-current 1.40.0, proposed).

## Context

Aegis 2.0.0 is NuGet `EchelonFoundry.Aegis.Core` (with `.Store.GitHub` and
`.Integration.GitHub`) 2.0.0 on nuget.org, published 2026-11-25 by aegis
`publish-nuget.yml` run 45531833809 from `f2c1fce3` (aegis#24). The package's
sha256 is `f0b5e1cbc365b3ededa2036102fb821486932e153335d3de4c3ef7eacee2ef02`
(re-hashed from the nuget.org download; Registry `releases/aegis/2.0.0.release.json`).

It is a major release:
- It adds `captureReported`, `Delivery`, `Termination`, `flush` and
  `forCommandLine`.
- The GitHub store replays idempotently, and stores fail closed.
- No public signature is removed or changed.
- The license changes from MIT (1.0.0) to PolyForm Noncommercial 1.0.0,
  embedded as a package license file.

Aegis is now a REG-RU-007 declared component in the Registry, because
consumers declare it in `conditor.json` (causa, gate-proof-r10,
indy-init-rehearsal-001). Released Conditor 0.10.25 qualifies only 1.0.0.

## Requirements

1. **Aegis 2.0.0 qualified.** 1.0.0 stays qualified as its upgrade source.
2. **Scaffold.** Under echelon-current 1.40.0, the kickoff manifest's engine
   project references `EchelonFoundry.Aegis.Core` 2.0.0.
3. **Re-lock.** The Aegis descriptor changes, so a project that declares
   Aegis runs `conditor init` once after installing the new Conditor
   release; its versions do not change. This is documented.
4. **echelon-current 1.40.0 qualified.**
   - The proposed set is vendored byte for byte from echelon-registry.
   - The kickoff manifest scaffolds under it.
   - A Conditor release carries the qualification for REG-RU-007.
   - The indy-init preset follows the channel (Aegis 2.0.0).

## Known limitation (not in scope)

`conditor upgrade --current` has no transition for a nuget.org-distributed
application binding:
- `NugetFeed` covers only GitHub release-asset libraries.
- A repository that declares Aegis 1.0.0 is therefore refused, not moved,
  under 1.40.0, and stays on its set until it migrates.

Adding a nuget.org binding transition (rewrite `PackageReference` /
`PackageVersion` and `conditor.json` together, prove the target is
qualified) is recorded as follow-up work.
